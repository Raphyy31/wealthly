**Plan d'action complet — Wealthly**
Établi le 2026-05-18 après audit complet (UI/UX + animations + architecture) sur la base du CSV de 204 transactions corrigées manuellement.

22 chantiers, 6 phases, ~25 sessions au total.

UI/UX d'abord (Phases 1→3), puis data (Phase 4), features (Phase 5), dette technique en parallèle (Phase 6).

---

## PHASE 1 — Foundations UI/UX (~3 sessions)

### Chantier 1 — Tokens transversaux dans le code
**Objectif** : codifier 8 thèmes design system dans `frontend/src/index.css` sans casser l'existant.
**Livrables** :
- 2 modes densité (`data-density="data|narrative"`)
- Scale typo formalisée `--text-2xs..hero` (8 niveaux)
- Dataviz étendue `--d8` teal + `--d9` olive + softs `--dN-soft`
- Focus ring canonique (`--focus-ring`) + press feedback (`filter: brightness`)
- Audit visuel sur Dashboard (vue témoin)

**Effort** : 1 session.

### Chantier 2 — Composants atomiques canoniques
**Objectif** : 1 façon de faire par primitive, documentée.
**Livrables** :
- `.card` + variants `--kpi`, `--insight`, `--drilldown`
- Pattern table "relevé" (header mono uppercase, body dotted divider, sticky blur)
- Modal scale 0.97→1, drawer clip-path reveal
- Inputs unifiés (states focus/disabled/error documentés)
- ChipSelect + Combobox + CategoryDropdown harmonisés

**Effort** : 1 session.

### Chantier 3 — Système numérique (tabular-nums level 2)
**Objectif** : 3 précisions documentées, signe explicite, deltas sémantiques.
**Livrables** :
- Helper `fmtAmount(value, mode: 'hero'|'card'|'inline'|'delta')`
- Caractères delta `▲`/`▼` Geist Mono (jamais translateY)
- Notation compacte K/M pour mobile (cards)
- Audit cohérence sur Dashboard, Wealth KPIs, Monthly synthèse

**Effort** : 1 session.

## PHASE 2 — UI/UX par vue (~6 sessions)

### Chantier 4 — Dashboard (vitrine)
**Objectif** : hero plus dense en information, sections rééquilibrées.
**Livrables** :
- Hero net worth : Newsreader italic + 3 deltas inline (30j/3M/YTD) avec ▲/▼
- Section I (Allocation) : donut + chip légende + sous-couches
- Section II (Santé financière) : gauge HealthScore refondue + 5 critères
- Section III (Trésorerie mensuelle) : revenus/dépenses/épargne + ratio
- 4ème section "Insights" : 3 cards éditoriales (comparer mois, top mouvement, milestone)
- Empty states éditoriaux Newsreader italique

**Effort** : 1 session.

### Chantier 5 — Wealth (vue dense)
**Objectif** : découper 4 300 lignes en composants et clarifier les 5 onglets.
**Livrables** :
- Refonte navigation onglets (chips horizontales sticky en haut)
- Sous-composants : `<WealthOverview/>`, `<AssetsList/>`, `<LiabilitiesList/>`, `<AssetEditor/>`, `<LoanWizard/>`
- Pattern liste/détail unifié (clic row → drawer droite)
- Card actif unifiée avec sparkline 90 jours + PV %
- Wizard ajout actif refondu (3 étapes max, pas 5)
- Empty state "Ajoutez votre 1er actif" + suggestions

**Effort** : 2 sessions (gros chantier).

### Chantier 6 — Transactions (productivité quotidienne)
**Objectif** : table dense pro-grade + bulk actions.
**Livrables** :
- Mode densité `data` activé (rows 36px)
- Pattern table relevé (header mono, dotted divider, sticky blur)
- **Bulk actions** : sélection multi-row → recat / flag récurrent / flag transfert / supprimer
- Filtres avancés : raccourcis date (7j/30j/3M/YTD), montant slider, multi-cat AND/OR
- Inline edit catégorie (clic pill → popover, pas modal)
- Vue mobile : cards compactes 2 lignes (date+payee, montant+cat)
- Badge source catégorisation : repolissage visuel

**Effort** : 1 session.

### Chantier 7 — Monthly / Suivi mensuel
**Objectif** : prédictif vs constaté plus clair.
**Livrables** :
- Carrousel mois sticky → switch vers vue calendrier mois entier (option toggle)
- Synthèse hero : 4 KPI (revenus, dépenses, épargne, ratio 50/30/20)
- Comparatif M-1 / Moyenne 3M sur chaque ligne
- Graphe budget vs réel par catégorie (Recharts BarChart horizontal)
- Sous-groupes pliables : indicateur progression sur header
- FixedChargeEditor refait (modal plus large, dual-column)

**Effort** : 1 session.

### Chantier 8 — Settings (refonte sections + découpe)
**Objectif** : sortir des 2 100 lignes monolithiques.
**Livrables** :
- Découpe sous-composants : `<BankConnections/>`, `<MyCategoriesSection/>`, `<CustomRulesSection/>`, `<PayeesSection/>`, `<MembersSection/>`, `<SecuritySection/>`, `<PreferencesSection/>`
- Navigation latérale section sticky (mobile : accordéon)
- Search global "Réglages" en haut (Cmd+K éventuel)
- Section Sécurité préparée pour 2FA TOTP (placeholder + CTA)

**Effort** : 1 session.

### Chantier 9 — Landing (acquisition)
**Objectif** : convaincre en 5s sans tomber dans le marketing creux.
**Livrables** :
- Hero refait : titre + sous-titre + 1 CTA + démo immédiate (live preview du dashboard cobalt sur dark)
- Section "Ce que vous voyez" : 3 captures animées (scroll-trigger sobre) — Dashboard / Wealth / Monthly
- Section "Sans pub, sans revente de données, self-hostable" — différenciateurs vs Finary/Lydia
- Pricing transparent (Solo/Famille/Pro/Admin) avec freemium clair
- FAQ contextuelle (sécurité données, GoCardless, comparaison)
- Footer minimal (légal + repo GitHub public)

**Effort** : 1 session.

## PHASE 3 — Animations GSAP progressives (~3 sessions)

### Chantier 10 — GSAP foundations
**Objectif** : poser les fondations propres, dégager Framer Motion.
**Livrables** :
- `npm install gsap` (core uniquement)
- `frontend/src/utils/gsapSetup.js` avec `gsap.matchMedia()` global + reduced-motion guard
- Migration `AnimatedNumber.jsx` rAF → `gsap.to({val}, {snap, ease: 'power2.out'})`
- Suppression `framer-motion` du package.json + audit imports orphelins
- Convention `data-animate="fade|scale|stagger"` documentée

**Effort** : 1 session.

### Chantier 11 — Micro-interactions
**Objectif** : choreography subtile sans translateY.
**Livrables** :
- Modal entry/exit timeline (backdrop 180ms + body scale 0.97→1 220ms)
- Drawer (AccountDrawer, WealthItemDrawer) : clip-path reveal
- Toast enter/leave (slide horizontal + opacity, autoremove onComplete)
- Sidebar active bar (cobalt 3×18) glisse entre items (`gsap.to({y})`)
- Page transitions (fade 0.25s sur switch de hash)

**Effort** : 1 session.

### Chantier 12 — Dataviz signature
**Objectif** : 3 animations emblématiques finance.
**Livrables** :
- HealthScore : timeline count-up sur le nombre + arc draw (`strokeDashoffset`) synchronisé
- NetWorthChart : draw-line progressif sur path (override Recharts)
- Sankey Cashflow : reveal nodes par stagger 0.05 (entrée seulement)
- Toutes respectent `prefers-reduced-motion` via matchMedia

**Effort** : 1 session.

## PHASE 4 — Data & logique métier (~4 sessions)

### Chantier 13 — Catégorisation : règles manquantes + edge cases
**Objectif** : combler les 11 trous identifiés dans le CSV.
**Livrables** :
- Patch `backend/app/defaults.py` : règles PRET CA, BNP PF, PREDICA, FRAIS IRREG, Intérêts débiteurs, Helium, NYX/SELECTA
- Sous-cat "Snacks & distributeurs" sous Restaurants
- Sous-cat "Primes/intéressement" sous Revenus
- Décision Swile : compte employeur séparé OU flag `is_employer_funded`
- Décision AMEX : règle conditionnelle (interne si AMEX synchronisé, sinon Shopping)
- Décision PayPal *Paiement 4X : tag "PayPal opaque" + non catégorisé
- Re-run du moteur sur le CSV → mesure taux `unknown` avant/après

**Effort** : 1 session.

### Chantier 14 — Récurrent vs FixedCharge : unification
**Objectif** : 1 seul modèle mental, 2 mécanismes au lieu de 5.
**Livrables** :
- Décision arch : (a) supprimer bouton récurrent + tout via FixedCharge, (b) coupler bouton → propose création FixedCharge, (c) garder mais clarifier UI
- Si (b) : workflow "tu as flaggé 3× → créer la FixedCharge ?"
- Inverse : FixedCharge créée → auto-flagge ses tx matchées
- Suppression / dépréciation SubscriptionsWidget si redondant avec Recurring view
- Cleanup `Recurring.jsx` ou repositionnement

**Effort** : 1 session (décision) + 1 session (implémentation).

### Chantier 15 — Transferts internes : refonte conceptuelle
**Objectif** : 1 source de vérité, UX claire pour l'override.
**Livrables** :
- Doc archi : qui décide ? (frontend detect / backend rule / role compte / override) → priorités
- Suppression des redondances (peut-être : supprimer detect frontend si rules backend suffisent)
- UX : panneau "Mouvements internes du mois" devient interactif (drag pour pairer, undo)
- Cas spécial Revolut card : auto-pair avec sync Revolut quand connecté
- Cas spécial AMEX : auto-flag tx avec libellé `AMERICAN EXPRESS`
- Tests pytest backend (cross-household isolation + idempotence)

**Effort** : 1 session.

## PHASE 5 — Features & finition (~4 sessions)

### Chantier 16 — Brainstorm nouvelles features
**Objectif** : feuille de route produit étoffée. Sélection au choix.
**Livrables candidats (à débattre)** :
- **Compte employeur Swile** (lié Chantier 13)
- **Vue famille consolidée** : superposer patrimoines des membres adultes
- **Alertes intelligentes** : "Franprix +40% ce mois", "Loyer non débité au J+5"
- **Partage budget couple** : 2 comptes, 1 budget commun, répartition au prorata revenus
- **Projection retraite** : combien à 65 ans selon ton rythme épargne ?
- **Simulateur achat immo** : capacité + reste à vivre + impact net worth 10 ans
- **Scan ticket de caisse** : OCR + auto-catégorisation (Claude vision)
- **Coffre-fort documents** : factures, baux, justificatifs (Supabase Storage)
- **Mode "Couple"** : 2 logins, vue mixte, virements internes auto-mappés

**Effort** : 1 session ideation + 1 session implémentation par feature retenue.

### Chantier 17 — Micro-frictions UX
**Objectif** : polir les 10 derniers % qui font la différence.
**Livrables** :
- Onboarding refait : 3 étapes max, démo skipable, "import mes 50 dernières tx" en 1 clic
- Empty states éditoriaux partout (Newsreader italic, ton sobre, CTA discret)
- Raccourcis clavier : `g d` = Dashboard, `g t` = Transactions, `/` = search, `?` = help
- Mobile bottom nav : décision 6 slots ou 5+Plus overflow
- Toast actions : annuler une recat / suppression sous 5s
- Loading states : skeleton screens vs spinners (skeleton pour data lourdes)

**Effort** : 1 session.

### Chantier 18 — Accessibilité + Performance
**Objectif** : Lighthouse > 95 sur 5 vues, WCAG AA validé.
**Livrables** :
- Audit axe-core + Lighthouse Dashboard / Wealth / Transactions / Monthly / Landing
- Contraste cobalt-soft sur fonds papier-chaud (validé AA)
- `aria-live` sur toasts, `aria-busy` sur sync, dialog roles sur modales
- Navigation clavier complète (focus trap modales)
- Code splitting : Wealth + Monthly + Settings en lazy chunks (TaxSimulator déjà fait)
- Bundle audit : analyzer + drop unused

**Effort** : 1 session.

## Audit synthétique (origine du plan)

**Forces actuelles** :
- Design system v3 papier chaud + cobalt cohérent et documenté
- Backend FastAPI + sécurité solide (JWT cookies, HIBP, rate limit, audit log)
- Catégorisation v2 sophistiquée (5-layer engine + 120 règles builtin)
- 8 modules pytest backend, bonne couverture sur chantiers critiques
- ROADMAP.md + CLAUDE.md disciplinés (sessions tracées, "things that bite")

**Problèmes identifiés** :
- `Wealth.jsx` 4 300+ lignes, `Settings.jsx` 2 100+ lignes (oversize)
- Pas de tests frontend (taxFr.js critique sans coverage)
- 2FA TOTP backlog persistant
- Routage hash artisanal (pas React Router)
- Pas de TypeScript (bugs camelCase/snake_case réels)
- 5 surfaces qui parlent de "récurrent" (redondance conceptuelle)
- Transferts internes : 4 mécanismes qui se chevauchent

**Direction visuelle** : papier chaud + cobalt `#2540D9` comme base à itérer (pas figée malgré CLAUDE.md). Geist + Newsreader italic, tabular-nums, no-translateY.
